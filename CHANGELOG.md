## v0.68.2

- fix: **the idle-close reaper now logs what it skipped, so an over-bar session that was not closed says why.** `IdleCloseReaper.Reap` called `IdleReaperJob.Tick` and mapped only `result.Closed`, so a tick that skipped every session wrote nothing — `job=idle-reaper action=tick closed=N skipped=N reasons=…` stopped at 2026-11-20 19:00:33 when `ReaperJob` replaced `IdleReaperJob`, and 622 such lines before it versus zero after is the whole record of the regression. The tick now records each skipped session with its reason (`IdleReaperResult.SkippedSessions`), the adapter writes the summary line itself in the idle job's own shape, and a **notable** skip — headless, still alive, at or past the floor, i.e. one that should have been closed — is returned as a `kept` result so `ReaperJob` renders `result=kept id=<sid> reason=<reason>`. Benign skips (interactive tabs, under-floor children, exited children) stay summary-count-only: a live tick skips ~37 sessions and a line each would drown the log. Floor, interval and `idleReapSkipReason` unchanged; the close path is untouched. Change set: `pkg/idle_reaper.go`, `pkg/keepalive_reaper_adapters.go`, `pkg/idle_reaper_observability_test.go` (new), `CHANGELOG.md`.

## v0.68.1

Change set: `pkg/liveness_verdict.go`, `pkg/liveness_verdict_test.go`, `CHANGELOG.md`.

## v0.68.0

- feat: **`GET /api/1.0/openable` exposes the flagged tick's per-row open decision as a read endpoint.** The tick computes every cycle whether each candidate row would be opened or held, and why, but discarded that into a log line — so a manager re-derived it by hunting the vault and the wrapper log, and a row the board showed as closed was held as `not-absent-dead` with no way to read the verdict. The endpoint returns one entry per candidate row (`vault`, `kind`, `name`, `session_id`, `decision` `open|held`, the tick's own `reason`, `phase`, `flag_set_by`) from the same `classify()` gates the tick uses, so the tick and the endpoint share one decision function. Read-only; `FlaggedRow` now carries the page's raw `flag_set_by`. Change set: `pkg/openable.go` (new), `pkg/handler/openable.go` (new), `pkg/openable_test.go` (new), `pkg/flagged_rows_source.go`, `pkg/flagged_rows_vaultapi.go`, `main.go`, `CHANGELOG.md`.

## v0.67.5

- fix: **a row the tick holds `parked-until` now gets its deadline written back as `defer_date`, so it hides itself and reappears on schedule instead of being reopened to rediscover the same wait.** The tick already parsed the clock out of the closer's `⏰ Ends:` (`ClassifyParked` → `ParkedDeclaration.Deadline`) and already held the row on it — but nothing wrote the field down, so `DefaultVaultAPITaskQuery` (`flag=true&status=in_progress&due=now`) kept returning the row and the tick reopened it. Measured 2026-11-26 on `seibert-brogrammers` *Lower lib-k8s Default CPU Request to 10m*: **8 opens in 11 h** (`00:26, 02:56, 04:56, 06:10, 07:41, 08:40, 09:56, 11:26`), every one ending `turn closed with nothing pending`, with no `defer_date` on the row at any point. The write happens in `parkedGate.Hold` only after the probe reports the clock has not passed, and only for `ParkedUntil` with a non-nil `Deadline` — a `parked-on-card` or `parked-on-pr` row is released by its probe, not by a clock, and a nil deadline is `ClassifyParked`'s cannot-address fallback. `VaultCLIDeferWriter` shells `vault-cli --vault <v> <kind> defer <name> <RFC3339>`, choosing the verb from the row's kind — `task`, `goal` and `topic` defer are three separate commands, and a hardcoded `task` would send a goal row's name to the task resolver and fail silently behind the fail-open gate. It is the same shell-out idiom `spawn_bind.go` uses for `claude_session_id`, so vault-cli stays the single writer of frontmatter; the full instant is stored, never the date-only form. A row whose `defer_date` has not expired is never overwritten (`FlaggedRow.DeferDate` + `sweepgate.IsDeferred`); an expired one is replaced, because a dead park is not a schedule. Fail-open throughout: a failed write, a missing `vault-cli` or a nil `Defer` leaves the hold exactly as it was. Not covered: a closer whose `⏰ Ends:` names no clock has a nil `Deadline`, so it writes nothing. Change set: `pkg/parked_defer.go` (new), `pkg/parked_gate.go`, `pkg/flagged_rows_source.go`, `pkg/flagged_rows_vaultapi.go`, `pkg/parked_defer_test.go` (new), `CHANGELOG.md`.

The in-process episode memory hides it until a restart, and then it does not. Measured 2026-11-26 on the shipped escalation: cards `cedf31eb…` (17:58:22) and `a7f38710…` (18:21:08) carry the identical dedup key `stalled|9175720d-…|ac388c8e722056bb`, the second posted after the daemon restarted at 18:19:08 — both now `closed`. ## v0.66.4

- fix: **a write to a child's stdin is bounded, so one child that stops reading can no longer wedge the flagged tick.** The daemon wrote through the same FIFO descriptor it handed the child; os/exec's `Fd()` call made that descriptor blocking, and on darwin a FIFO never enters Go's poller (golang/go#24164), so the write had no deadline at all. Measured 2026-11-26: the flagged tick's goroutine sat 67 minutes in `(*child).send` → `syscall.write` while the daemon stayed up, and every flagged row flagged after 08:32 went unopened. The store now opens the FIFO twice — a blocking descriptor for the child, and a non-blocking one the daemon writes through (`fifoWriter`), which retries a full FIFO until a 30 s deadline. A write that misses it returns `ErrSendTimeout` and marks that child's stdin broken (a partial line may sit in the FIFO), so the spawn is refused instead of waited on; a stdin that cannot take a deadline is refused rather than written unbounded. Both writers, `send` and `writeControl`, go through the one bounded `writeLine`. Change set: `pkg/fifo_writer.go` (new), `pkg/sessionstore.go`, `pkg/supervisor.go`, `pkg/errors.go`, `pkg/send_deadline_test.go` (new — a real child that never reads its stdin), `pkg/zero_turn_test.go`, `CHANGELOG.md`.

  already-answered request, and leaves the request unanswered.

## v0.3.0

- feat: serve a client-facing MCP face at `/mcp` on the daemon's own mux, over streamable HTTP, so an
  MCP client (Codex) can drive a Claude session instead of only REST. Five tools —
  `spawn_session`, `send_message`, `list_sessions`, `get_session`, `kill_session`. This is the
  opposite direction from `--mcp-stdio`, which is child-facing: that one gives a child a permission
  tool, this one lets a client drive a child.
- feat: `send_message` returns the assistant text that closed the turn, taken from the child's
  `result` event. The REST `POST …/message` route answers `202 {"status":"sent"}` and carries no
  answer, so this is the one tool that cannot delegate to it.
- feat: a turn that never closes returns a tool error naming the timeout (`--mcp-turn-timeout`,
  default 120s) rather than a success. The write deadline is cleared for the duration of a call,
  because the turn deadline deliberately outlasts the server's 60s `WriteTimeout` and a response
  written after it would never reach the client.
- fix: `/mcp` rejects a non-loopback `Host` or `Origin`, a socket whose own local address is not
  loopback, and a body that is not declared `application/json`. A localhost HTTP server is
  otherwise reachable by any browser page through DNS rebinding, which with `spawn_session` on
  the other end is remote code execution as the daemon user. An oversized body answers `413`
  rather than being truncated into a parse error.
- fix: `send_message` refuses a session whose child already has a turn open. The session lock
  excludes other writers, but the timeout path releases it while the child is still generating —
  writing then would open a second turn on top of the first and make the two results
  indistinguishable.

## v0.2.0

- feat: run a named macro — a fixed, ordered list of user turns — against one child, writing each step
  only after the previous turn's `result` event arrives. Until now the wrapper could send one turn
  and watch, so a sequence like `/vault-cli:prepare-compact` → `/compact` →
  `/vault-cli:post-compact` had to be driven by hand: a timer cannot do it, because a compaction's
  duration is unpredictable and a delay short enough to be safe fires the next command mid-turn.
  The endpoint takes a macro name rather than a command list (`compact`, `terminal`) because it can
  drive `/exit`, so what it is able to run stays reviewable as a diff. Both macros contain a
  production-touching step and are refused with 409 without `confirm`; the call blocks and answers
  with every step, naming the ones a stopped run never reached.

## v0.1.0

- feat: let a spawn hand the child its own environment, resume an existing conversation, and load
  extra MCP config files. Each closes a silent divergence: without `env` the child inherits the
  wrapper's environment instead of the one its caller resolved; without `resume` a conversation
  cannot be continued through the wrapper at all; without `mcp_configs` a launcher's own
  `--mcp-config` file — a CLI flag, so no setting source can reach it — is absent and the child
  runs with fewer servers than its hand-started twin. A malformed `env` key or value, a
  flag-shaped MCP config entry and a non-UUID `resume` are refused with 400 rather than reaching
  the child's argv: `--mcp-config` is variadic, so an entry beginning with `-` would be parsed as
  a flag and silently change the child instead of being rejected.

- Stream a session's events over `GET /api/1.0/sessions/{id}/events` (server-sent events),
  replaying what the child has already emitted before the live frames. Until now the wrapper
  folded every event into `state` and discarded it, so a supervisor could read a child's state
  but never the turn that produced it — which is why replacing an in-process `query()` with a
  wrapper-backed spawn left the supervisor blind to the child it supervises.

- Expose `last_event_age_seconds` per session, so a caller can tell a genuinely idle child
  from one that is busy inside a tool call. State is never derived from it — that inversion is
  the defect the field makes visible.
- Conform to the house style the first cut skipped: inject the clock instead of calling
  `time.Now()`, return an interface from `NewPending`, use Ginkgo for the handler tests, and
  build the sentinel errors without a package-level `context.Background()`.
- Initial cut: a standalone Go service that owns a `claude` child process and exposes it over REST.
  Spawn, list, inspect and stop sessions; `state` is derived from the child's own event stream
  (`generating` while an assistant turn is open, `idle` when it closes) rather than from the age of
  its last event, which is what made a worker generating for forty minutes read as idle.
